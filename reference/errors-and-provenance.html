Reporting a subagent failure (5.3, sample Q8)

PatternVerdict
Empty result marked as success✗ The failure is suppressed and the report looks complete
Retries, then a generic "search unavailable"✗ Hides which query failed, what still worked, and what to try
Exception to a top-level handler that ends the run✗ One failure throws away every other result
Structured: failureType, attemptedQuery, partial results, alternatives✓ The coordinator can choose to retry, use another source, or proceed and annotate

Subagent: retry transient failures locally, and propagate only what it can't resolve. Coordinator: owns the recovery decision. Re-delegate once with an alternative, then proceed with partial results. Never abort the whole run.

"Nothing exists" and "couldn't look" must never share wording. That is the same distinction as Lesson 2's isError versus results: [], one level up.

Provenance (5.6)

  • Finding = { claim, evidence, source: { id, publisher, published: YYYY-MM-DD, page } }. Every hop must preserve and merge it.
  • Attribution is lost at summarization steps, and every handoff is one, including the coordinator's final rewrite.
  • Conflicts: keep both values, each with its source. Never pick, average or drop one. A subagent completes its analysis with the conflict annotated, and the coordinator decides how to reconcile before synthesis.
  • Dates turn a false "contradiction" into a trend. Keep each source's methodological context (sample size, what was actually measured).
  • Report sections: well-established · contested · coverage gaps. Figures as tables, news as prose, technical findings as lists.

Context between agents (5.1, multi-agent parts)

  • Upstream agents return structured key facts, citations and relevance, not reasoning chains. Subagents return roughly 1–2k tokens.
  • Trim verbose tool output to the relevant fields before it accumulates (40 fields → 5).
  • Lost in the middle: put the key-findings or coverage summary first and use explicit section headers. Long data at the top, the query at the end.
  • Require metadata (dates, source locations, method) in subagent output.
  • Lesson 11 "Case facts" block outside summarised history, and multi-issue state, for customer sessions.

Exam: choose the structured-output design answer. Reality: prompt for the structure, then validate it in code.

Distractors: average conflicting values; prefer the newest or biggest; drop contested statistics; a bibliography without claim links; give synthesis web search; a bigger context window for lost-in-the-middle; self-rated confidence in error reports.
