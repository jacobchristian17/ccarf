MCP integration, built-in tools & plan mode

A one-page cheat sheet, taught in Lesson 8. For MCP, decide who gets each server and where its secret comes from. For a task, decide which tool finds it and whether to plan first.

MCP scopes (2.4)

ScopeStored inWho gets itUse for
Project.mcp.json at the repo rootEveryone who clones (git)Shared team tooling
User~/.claude.json (top-level mcpServers)Only you, every projectPersonal / experimental servers
Local (not in the guide)~/.claude.json, under this project's entryOnly you, this projectDefault of claude mcp add

claude mcp add --scope project|user|local …. Precedence on a name clash: local > project > user. Interactive sessions ask for approval before using .mcp.json servers (claude mcp reset-project-choices). claude -p and the SDK don't ask. All configured servers connect together, and their tools are available simultaneously.

Secrets: env var expansion

{ "mcpServers": { "tally-index": {
    "command": "node", "args": ["${TALLY_TOOLS_DIR}/tally-index.mjs"],
    "env": { "TALLY_INDEX_TOKEN": "${TALLY_INDEX_TOKEN}" } } } }    # each dev sets it in their shell

Expansion works in command, args, env, url and headers. ${VAR:-default} gives a fallback, so never put a real token in the default. If the variable is unset, the config still loads, and the server receives the literal text ${VAR}, with only a warning in claude mcp list. A committed literal token is in every clone and in git history: rotate it.

Plan mode vs direct execution (3.4)

Plan modeDirect execution
Large-scale or multi-file changes, library migrations (45+ files), architectural decisions, several valid approaches with different infrastructure needsWell-scoped, clear changes: a one-file bug fix with a clear stack trace, adding one validation conditional

Plan mode is read-only exploration and design before any change, which prevents costly rework. Enter it with Shift+Tab, /plan, --permission-mode plan, "defaultMode": "plan", or SDK permissionMode: "plan". Combine them: plan the migration, then execute the approved plan directly. Use the Explore subagent (read-only) for verbose discovery, so only a summary lands in the main context.
