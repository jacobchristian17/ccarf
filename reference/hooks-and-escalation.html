Hooks, gates & escalation

One-page cheat sheet. Taught in Lesson 3.

Hook or prompt?

Hook / prerequisite gatePrompt (criteria + few-shot)
Financial, identity or compliance rule; "must never happen"Judgement: when to escalate, tone, ordering of concerns
Code can evaluate it from tool name + inputs + stateNeeds reading the conversation
Sample Q1: agent skips get_customer 12% → gateSample Q3: escalation miscalibrated → explicit criteria + few-shot

Distractors: stronger wording, more few-shot for a guarantee; self-reported confidence; sentiment thresholds; a separate classifier before prompts are fixed.

Agent SDK hooks (TypeScript)

EventReturn in hookSpecificOutputUse
PreToolUsepermissionDecision: "deny", permissionDecisionReason · or updatedInputBlock / redirect; prerequisite gate
PostToolUseupdatedToolOutput (replace) · additionalContext (append)Normalise formats; redact; record state
query({ prompt, options: { mcpServers: { support: server }, allowedTools: ["mcp__support__*"],
  hooks: { PreToolUse: [{ matcher: "^mcp__support__process_refund$", hooks: [cb] }] } } })
cb = async (input, toolUseID, { signal }) => ({ hookSpecificOutput: {
  hookEventName: "PreToolUse", permissionDecision: "deny", permissionDecisionReason: "… call escalate_to_human" } })
  • Matcher = regex on the tool name. MCP: mcp__<server>__<tool>. No matcher = every tool.
  • Deny reason reaches the model as an is_error tool_result → write it as a redirect.
  • Matching hooks run in parallel; any deny wins. PreToolUse timeout → the tool doesn't run.
  • MCP tool_response = content array [{type:"text",text}]. updatedMCPToolOutput is deprecated.
  • Return {} to allow / leave unchanged.

Prerequisite gate pattern

  1. PostToolUse(get_customer): exactly one match → state.verifiedId; else null (+ "ask for email" if >1)
  2. PreToolUse(order/refund tools): no verifiedId → deny "call get_customer first"; refund customer_id ≠ verifiedId → deny
  3. State is per session. Server-side rules stay as defence in depth.

Escalation (5.2)

TriggerMove
Explicit request for a humanEscalate immediately, no investigation first
Policy ambiguous / silent (competitor price match)Escalate; don't invent policy
No meaningful progress possibleEscalate with what was tried
Frustrated, but straightforward issueAcknowledge → offer to resolve → escalate only if they reiterate
Multiple customer matchesAsk for another identifier; never pick by heuristic

Not reliable: sentiment, self-reported confidence. Handoff (human lacks transcript): customer ID · root cause · refund amount · recommended action (+ actions taken). Enforce the shape with the escalation tool's schema.

Multi-concern: decompose into items → investigate each (parallel, shared context) → one unified reply.
