Tool descriptions & MCP error contract

One-page cheat sheet. Taught in Lesson 2.

Description checklist (≥ 3–4 sentences)

  • Does: what it does and what it returns (its shape)
  • When: when to use it, and when not to, naming the sibling tool
  • Input: formats with examples ('12345', a # is ok)
  • Edges: limits, what it doesn't return, what "empty" means, the business rules

Selection problems → first step

SymptomFix
Minimal descriptions, wrong tool pickedExpand the descriptions (sample Q2). Not a routing layer, few-shot, or a merge.
Near-identical descriptionsRename and re-describe: analyze_content → extract_web_results
One generic tool, many jobsSplit by purpose: extract_data_points / summarize_content / verify_claim_against_source
Misroutes on certain wordsReview the system prompt for keyword-sensitive instructions
Many thin API wrappers (docs)Consolidate into workflow tools. Rule: one tool per clear purpose

MCP: two error channels

ChannelForFormat
Protocol errorUnknown tool, malformed request, server errorJSON-RPC error, e.g. -32602
Tool execution errorAPI failure, invalid input, business ruleresult with isError: true and actionable text

The TS SDK turns a thrown handler error into isError: true with only the bare message. That's the uniform error: no category, no retry hint.

Error contract

{ errorCategory: "transient" | "validation" | "business" | "permission",
  isRetryable: boolean,
  message: string,           // for the agent: what happened and what to do
  customerMessage?: string } // business/permission: safe to say aloud
CategoryExampleRetryAgent does
transienttimeout, 503/504yes, boundedretry, then say it's temporary
validationbad id, amount > totalnot unchangedfix the input or ask the customer
businessover limit, outside windownorelay customerMessage, escalate if policy says
permissionsomeone else's ordernoreveal nothing, re-verify identity
unknownanything unmappednonever guess it's retryable; escalate

Empty ≠ error. A query that worked and found nothing returns success ({order: null}, []). An access failure returns isError.

Subagents (preview of L5): retry transient errors locally, and pass up only what's unresolved, with partial results and what was attempted.

MCP server skeleton (TypeScript)

import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "support", version: "1.0.0" });
server.registerTool("lookup_order", {
  description: "Fetch ONE order by order number… Do not use for identity: use get_customer…",
  inputSchema: { order_id: z.string().describe("Digits only, e.g. '12345'") },
}, async ({ order_id }) => {
  try { return { content: [{ type: "text", text: JSON.stringify({ order: getOrder(order_id) }) }] }; }
  catch (e) { return { isError: true, content: [{ type: "text", text: JSON.stringify(toToolError(e)) }] }; }
});
await server.connect(new StdioServerTransport());

Exam reflexes

  • Misrouting plus minimal descriptions → better descriptions first
  • "Operation failed" plus wasted retries → structured category + isRetryable
  • "Not found" treated as an outage → an empty result is a success
  • Financial rule only in a description → still needs deterministic enforcement (L3)
